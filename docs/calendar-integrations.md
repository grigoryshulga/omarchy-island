# Внешние календари для Island

Исследовано 12 ноября 2026. В этой итерации реализованы локальные напоминания Omarchy и просмотр года. Подключение внешних календарей пока не реализовано; ниже — проверенные варианты и предлагаемая архитектура.

## Рекомендуемый первый этап: подписки ICS

Google Calendar предоставляет публичный адрес iCal в настройках календаря: «Интеграция календаря → Общедоступный адрес в формате iCal». Это подходит для публичных праздников, расписаний и других календарей. Для чтения такого URL не нужен вход через Google. Источник: [Google — публичные календари](https://support.google.com/calendar/answer/37083?hl=en).

Приватный Google Calendar также можно читать через «Секретный адрес в формате iCal», если он доступен для аккаунта. Календарь при этом не нужно делать публичным. Такая ссылка даёт доступ к данным: её следует хранить как секрет, не показывать целиком в журнале и не помещать в экспорт обычных настроек. Это подписка для просмотра, а не способ редактировать события. Источник: [Google — просмотр через iCal](https://support.google.com/calendar/answer/37648?hl=en).

Для Island предлагается:

- Источники в настройках календаря: имя, HTTPS URL, цвет, включение и удаление.
- Общая модель событий отдельно от напоминаний: источник, UID, экземпляр повторения, начало/окончание, часовой пояс, признак «весь день», заголовок и место.
- Метки в сетках месяца/года; список событий выбранного дня под календарём. Локальные таймеры остаются отдельным блоком.
- Обновление при открытии и далее с ограниченной частотой, ручное обновление, ETag/Last-Modified, последний успешный кэш и явная отметка устаревания.
- Python-процесс в `plugin/bin/` для сети и разбора; QML отвечает только за состояние и представление. URL проходят централизованную политику Security; загрузчик повторно проверяет адрес и редиректы, ограничивает размер и время запроса.
- Для приватных подписок — защищённое хранилище, каталог `0700`, файлы `0600`. Никаких секретных адресов в уведомлениях, git или диагностических сообщениях.

Не стоит разбирать ICS регулярными выражениями. Стандарт включает TZID, события на весь день, повторения, исключения и изменённые экземпляры; окончание события может быть исключающей границей. Нужны тесты переходов DST, многодневных событий и повторений. Источник: [RFC 5545](https://datatracker.ietf.org/doc/html/rfc5545).

Кандидаты: [icalendar](https://icalendar.readthedocs.io/en/latest/) для чтения формата и [recurring-ical-events](https://recurring-ical-events.readthedocs.io/en/latest/) для раскрытия повторений в ограниченном диапазоне дат. Это новые зависимости; перед реализацией нужно определить их доставку в Omarchy и зафиксировать совместимые версии. На этапе исследования пакеты не устанавливались.

## Второй этап: Google Calendar API

Для выбора приватных календарей из аккаунта и последующего редактирования событий нужен OAuth-клиент приложения. Для desktop-потока Google описывает системный браузер, loopback redirect и PKCE; refresh token позволяет обновлять доступ без повторного входа. Потребуются Google Cloud project, включённый Calendar API и настроенный экран согласия. Источник: [OAuth для desktop-приложений](https://developers.google.com/identity/protocols/oauth2/native-app).

Начать стоит с прав чтения: `calendar.calendarlist.readonly` для списка и `calendar.events.readonly` для событий. Запись добавлять отдельно, когда в Island появится редактор событий. Источник: [области доступа Calendar API](https://developers.google.com/workspace/calendar/api/auth).

Для синхронизации API поддерживает начальную полную загрузку и дальнейшие изменения по `syncToken`; нужно учитывать пагинацию, удаления и сброс токена с повторной полной загрузкой при HTTP 410. Источник: [инкрементальная синхронизация](https://developers.google.com/workspace/calendar/api/guides/sync).

Собственный OAuth-клиент предпочтительнее использования токена из подключённого к ассистенту Google-коннектора: настольный плагин должен работать независимо от этой беседы. Токены следует хранить в системном Secret Service, а сетевой код и повторные попытки отделить от UI.

## Граница текущих напоминаний

`omarchy-reminder` — таймер «через N минут», а не календарное событие на выбранную дату. Island сохраняет это поведение и прямо подписывает его в форме. Существующие таймеры читаются через `show --json`; создание и `clear` выполняются тем же штатным CLI. Уведомления отправляет native systemd service, поэтому закрытие или перезапуск Island их не отменяет. Это runtime-таймеры Omarchy; Island не обещает сохранение через перезагрузку машины и не добавляет независимый планировщик.

Рекомендуемая последовательность: публичные ICS → приватные ICS с защищённым хранением → Google OAuth для чтения → редактор событий при необходимости.
